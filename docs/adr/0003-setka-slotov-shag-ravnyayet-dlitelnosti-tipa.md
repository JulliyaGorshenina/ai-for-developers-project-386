# ADR 0003: Сетка слотов строится с шагом, равным длительности типа события

- **Дата:** 2026-10-22
- **Статус:** принято

## Контекст

С появлением типов событий с разной длительностью (например, 30/45/60 минут) нужно
решить, как генерируются моменты начала слотов внутри окна доступности. Минимум
рассматривались две модели:

1. **Шаг = длительность типа**, отсчёт от начала окна.
2. **Фиксированный базовый шаг** (например, 30 минут): слот длиной типа ставится
   на каждую позицию сетки, где целиком помещается.

Модели расходятся заметно. Для окна 10:00–18:00 и типа на 45 минут: модель 1 даёт
10:00, 10:45, 11:30, …; модель 2 даёт 10:00, 10:30, 11:00, … — то есть при модели 1
тип не может начаться в 11:00.

## Решение

- **Шаг сетки равен длительности типа события** `D`; сетка отсчитывается **от начала
  окна доступности**.
- Слот предлагается, только если **целиком помещается** в окно; частичных слотов нет.
- Глобальный `SLOT_MINUTES` как шаг **отменяется** — длительность задаёт тип события.
- Каждое окно доступности порождает **собственную** сетку от своего начала, поэтому
  границы окон влияют на расположение слотов.
- Пересекающиеся окна доступности одного дня **отклоняются** (400) при сохранении
  расписания; смежные (встык) разрешены.
- Окно записи — **14 дней**, начиная с текущей даты; сегодняшний день включён, но
  предлагаются только слоты со временем начала позже текущего момента.

## Последствия

- Для типа 45 минут в окне 10:00–18:00 слоты: 10:00, 10:45, 11:30, …, 16:45.
- Порядок и границы окон в расписании значимы: одно и то же множество рабочих часов,
  нарезанное по-разному, даёт разные наборы слотов.
- Слот считается свободным, только если не пересекается ни с одной активной бронью
  (включая брони других типов событий) — см. ADR по занятости и тикет конфликтов.
